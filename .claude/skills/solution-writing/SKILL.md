# 解决方案写作（solution-writing）

为 FastGPT 生成**解决方案文章 / 方案**。动笔前先判断这份材料**给谁看、要什么结果**——这决定走哪一条线，两条线的很多原则是**相反**的。

## 先判断走哪条线

| 维度 | 公开通用（解决方案中心） | 私人定制（售前） |
| --- | --- | --- |
| 给谁看 | 大众，浏览中的潜在采购决策者 | 一个具体客户的高管 / IT / 采购 |
| 要什么 | 吸引 → 预约 POC → 转售前 | 成单（拿下这一个客户） |
| 核心判据 | 换了客户名仍**成立** | 换了客户名就**失效** |
| 数据来源 | 脱敏行业案例 + 保守估算 | 尽调客户真实数据 |
| 结尾动作 | 预约免费 POC（短 CTA） | 进入 POC / 补齐材料 / 确认验收口径 |
| 方法论 | `references/public-article.md` | `references/presales-custom.md` |

**当前解决方案中心（AI 智能报销、AI 翻译、AI 出题组卷、AI 导诊预问诊等公开案例）走「公开通用」这一条。**

> 一句话记忆：**私人定制要"换名失效"（证明你懂这一个客户），公开通用要"换名仍成立"（证明你覆盖这一类场景）。** 两条线共享写作质感（去 AI 味、细节锚点、指标三件套、真实感、痛点因链、人机分工、长尾边界），在各自文件里都有展开。

## 快速工作流

1. **判断路线**：看上面这张表，确定是公开文章还是售前方案。
2. **读对应方法论**：公开通用 → `references/public-article.md`；私人定制 → `references/presales-custom.md`。
3. **（公开通用）先写「选题卡」，再按五章骨架填血肉**；配图走项目 skill `solution-illustration`。
4. **交付前过一遍对应文件末尾的检查清单**。

## 输出位置

- **生成的文章直接写到 `docs/<行业>/<文章>.mdx`**，文件名按选题 `AI <场景>.mdx`，`sidebar_position` 按该行业目录现有文章顺延。
- **行业目录**：`0.IM 连接器` / `1.企业通用` / `2.教育行业` / `3.医疗行业`（通用场景如会议纪要、合同审查、销售开单 → `1.企业通用`）。
- **文章配图**放文章同目录的 `assets/` 下，用相对路径 `./assets/<图>.jpg` 引用（不放 `static/img/`）。
- **售前方案**按客户单独成文，不落 `docs/`（作为单独交付物给出）。

## 详细方法论

- 公开通用（解决方案中心案例文章：五章骨架固定血肉可变、正文 1200–1800 字、图表选型、对抗性自测）：`references/public-article.md`
- 私人定制（售前方案：尽调客户、痛点因链、ROI 回本、高管共鸣、承诺可验收）：`references/presales-custom.md`
