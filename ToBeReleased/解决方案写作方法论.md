# 解决方案写作方法论（入口）

> 写方案之前，先判断这份材料是给谁、要什么结果——这决定你走哪一条线。两条线的很多原则是**相反**的。

| | 私人定制（售前） | 公开通用（解决方案中心） |
| --- | --- | --- |
| 给谁看 | 一个具体客户的高管/IT/采购 | 大众，浏览中的潜在采购决策者 |
| 要什么 | 成单（拿下这一个客户） | 吸引 → 预约 POC → 转售前 |
| 核心判据 | 换了客户名就**失效** | 换了客户名仍**成立** |
| 数据来源 | 尽调客户真实数据 | 脱敏行业案例 + 保守估算 |
| 结尾动作 | 进入 POC / 补齐材料 / 确认验收口径 | 预约免费 POC（短 CTA） |
| 方法论文件 | [解决方案写作方法论-私人定制.md](./解决方案写作方法论-私人定制.md) | [解决方案写作方法论-公开通用.md](./解决方案写作方法论-公开通用.md) |

**当前解决方案中心（报销助手、智能客服、合同审核等公开案例）走的是「公开通用」这一条。**

> 两条线共享的写作质感（去 AI 味、细节锚点、指标三件套、真实感、痛点因链、人机分工、长尾边界）在各自文件里都有展开，直接读对应那份即可。
>
> 一句话记忆：**私人定制要"换名失效"（证明你懂这一个客户），公开通用要"换名仍成立"（证明你覆盖这一类场景）。**
